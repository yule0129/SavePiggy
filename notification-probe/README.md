# 微信通知限时验证包

当前版本 0.2.0，面向 vivo S9 Android 13 OriginOS 3、微信 8.0.68 的数据来源验证。独立于 Expo 账本，不会自动入账或操作微信。

## 权限与隐私边界

系统通知使用权范围较广，代码中的微信过滤不等同于系统仅授予微信权限。用户不接受这一范围时应停止测试，继续使用手动或文件导入。

- 默认不处理通知，必须在应用中主动开始 5 分钟测试。到期停止处理，进程重启后不会恢复。
- 在测试期间，其他应用的事件直接忽略。微信事件仅统计数量；只有通知标题严格等于“微信支付”或“WeChat Pay”才读取正文以提取金额。
- 不持久化通知原文、联系人、商家或交易号。不联网、不上传，自动备份关闭。
- 候选金额只在内存保留最多 20 个，停止或到期清除。到期后的内存清理依赖进程回调执行，后续读取和事件处理也会检查截止时间。
- 标题可被聊天昵称等模仿，候选金额也可能包含余额等其他数值，不能当作已验证付款或正式账单。
- 验证页使用 FLAG_SECURE 限制截图及最近任务预览。没有完整真机或独立安全审计，不能保证零风险。
- 停止测试按钮只关闭本程序处理，不能撤销系统通知使用权。用户需在系统设置中手动关闭该权限，或卸载应用。
- 打开新版会清空旧版的本机验证日志。普通存储清除不等同于存储介质的取证级擦除。

## 构建与验证

使用本机 F 盘 SDK 与 Android Studio 的 Java，所有 APK、调试签名及编译产物在已忽略的 build 目录，不下载 Gradle。

```powershell
powershell -ExecutionPolicy Bypass -File F:\SavePiggy\notification-probe\build.ps1
```

独立测试源码在 test/PaymentTextTest.java，验证严格标题筛选、金额格式和普通数字排除。APK 编译与签名通过不等于真机运行或支付通知可用。

## 用户测试

1. 若仍有顾虑，保持未安装、未授权状态，不必继续。
2. 如愿意测试，手动安装版本 0.2.0，阅读应用说明，再自行决定是否开启系统通知使用权。
3. 返回应用，主动点击开始 5 分钟测试；仅在正常消费时观察系统通知，不必额外消费。
4. 比对候选金额是否符合真实付款；没有候选时不能算成功。
5. 结束后停止清空，并在系统设置关闭通知使用权。不再开发时关闭 USB 调试。

正式自动记账仍需在数据来源验证后实现后台队列、可靠解析、去重与分类确认。

## 当前真机反馈

2026 年 11 月 4 日，用户在 vivo S9 Android 13 OriginOS 3、微信 8.0.68 上反馈：

| 场景 | 用户观察 | 当前判断 |
| --- | --- | --- |
| 商家付款 | 能获取金额 | 具备继续开发付款通知接入的依据，尚未完成多笔准确性与后台稳定性验证 |
| 转账 | 能识别 | 需与商家消费分开处理，不能因为出现金额就直接记为消费 |
| 发红包 | 微信通知事件没有增加 | 当前通知监听方案不覆盖该场景，不能靠金额解析规则补齐 |

这些是用户操作反馈，不是自动化测试或对所有设备的支持承诺。下一步需确认真实付款通知中的成功状态、金额上下文、是否包含多个金额，以及通知更新和重复事件的表现。仅在金额与消费类型明确后生成待记账，用户分类确认后再计入正式支出。继续保持通知原文不落盘、不上传；诊断程序仍为手动开启的限时模式。

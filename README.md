# SavePiggy

一款面向 iPhone 用户的轻量记账 App，目标是在付款成功后提醒记账，自动预填金额，由用户选择支出类型后确认保存。

**项目状态：交互原型开发阶段。`mobile/` 已加入 Expo Go 记账原型，包含模拟付款、分类保存、账单管理和本地存储；真实支付接入尚未实现。下文原生选型、完整功能范围和排期是原始规划，需结合原型验证调整。**

## 手机原型快速开始

电脑浏览器预览：进入 `mobile` 目录运行 `npm run web`，无需手机扫码。模拟付款、分类和账单数据可在浏览器中体验；浏览器与手机的本地数据不互通。

```powershell
cd F:\SavePiggy\mobile
npm install
npx expo login
npm start
```

iPhone 安装 Expo Go，与电脑连接同一个 Wi-Fi，并登录同一 Expo 账号后扫描终端二维码。详见 [手机原型启动与验收说明](mobile/README.md)。这一阶段使用 Expo 与 React Native，在 Windows 开发；后续自定义原生能力使用开发构建和云端构建验证。

- 项目仓库：[yule0129/SavePiggy](https://github.com/yule0129/SavePiggy)
- 首发平台：iOS
- 目标用户：希望了解日常开销，但不愿每次付款后手动填写金额的用户
- 文档更新日期：2026 年 10 月 26 日

## 项目目标

SavePiggy 希望减少记账操作，同时保留用户对账单和分类的确认。它面向可分发给其他用户的产品开发，需要考虑不同设备、系统版本、支付渠道和权限状态。

首版优先验证并实现“获取付款信息 → 提醒 → 预填 → 分类 → 保存”这条流程。只有用户确认保存的记录才计入正式收支统计。

## 核心使用流程

```text
用户在支付 App 中付款成功
          ↓
通过支持的系统入口获取交易信息
          ↓
校验金额和交易状态，并识别疑似重复记录
          ↓
生成待记账记录，在条件允许时发出记账通知
          ↓
用户点击通知进入 SavePiggy
          ↓
查看预填金额，手动选择支出类型
          ↓
点击保存，更新账单和月度统计
```

例如：付款 28 元后收到“支出 ¥28，点击分类并记账”的通知。点击进入 App 后金额已填好，选择“餐饮”并保存即可。金额可修改，分类由用户确认。

用户没有立即处理时，记录保留在“待记账”列表中，可稍后保存或忽略。通知不是强制操作，未确认记录不计入正式支出。

## iOS 能力边界与兼容策略

**安装记账 App 不会自动获得其他 App 的支付流水。自动提醒的前提是存在可用的系统触发入口，并且能够取得可靠的交易信息。**

付款提醒优先采用可点击的系统通知。通知展示形式由系统设置和运行条件决定，不以任意覆盖其他 App 的弹窗或强制跳转作为产品承诺。进入记账页由用户主动点击触发。

兼容性分为两个维度：App 可安装运行的系统范围，以及自动提醒可覆盖的系统和支付场景。最低 iOS 版本将在第一阶段验证后确定；较新的能力按系统可用性启用。

| 接入方式 | 计划用途 | 关键限制与待验证项 |
| --- | --- | --- |
| Apple 钱包交易自动化 | 为适用的钱包交易提供记账入口 | 需验证触发时机、可用字段和付款场景；触发本身不能直接视为最终扣款成功 |
| 快捷指令通知自动化 | 从支持系统上的指定 App 通知提取交易信息 | 需用户配置；验证能否传入完整金额和状态；App 内消息不等同于系统通知 |
| 支付截图分享 | 将付款截图分享到 App，识别金额后分类保存 | 用户主动分享；OCR 可能识别错误，需校验或确认；分享扩展能力也需验证 |
| App 内快捷记账 | 在没有可用自动化入口时完成记账 | 金额需要手动输入，保障基础功能可用 |

微信、支付宝、Apple Pay 是首批目标验证渠道，**不表示已全部接入或能够覆盖每次付款**。无交易信息时不编造金额，无通知权限时仍可通过待记账列表处理已经接收到的记录。

不采用越狱、私有接口、未经授权读取其他 App 数据等方式实现核心功能。付款截图只在用户主动提供后处理。

## 页面规划

1. **首页**：本月净支出、最近账单、待记账数量、快速记账入口。
2. **记账页**：金额、币种、商家、时间、支付渠道、支出类型、备注和保存按钮；无法取得的字段允许为空。
3. **待记账页**：集中处理未确认记录，支持忽略，显示疑似重复提示。
4. **账单页**：按日期浏览，按分类和渠道筛选，查看及编辑详情。
5. **统计页**：月度汇总与分类占比，明确统计口径。
6. **设置页**：记账入口配置、兼容情况、测试流程、分类管理、数据导出恢复和隐私设置。

默认分类建议：餐饮、交通、购物、住房、娱乐、医疗、学习、其他。相同商家的历史分类可作为建议，但不自动代替用户确认。

## 账单规则与异常处理

- **记录状态**：待确认、已入账、已忽略。交易是否完成与记账状态分别存储，避免把触发事件误当成支付成功。
- **金额**：使用十进制定点表示或按币种精度存储的整数，避免二进制浮点直接计算；首版以人民币为主，多币种汇率换算后续规划。
- **去重**：优先使用来源交易标识；缺少标识时综合金额、币种、时间、商家和渠道判断。金额相同不代表同一笔交易，存在歧义时提示确认。
- **退款**：保留退款记录，可关联原支出；支持部分退款。月度净支出按发生在该月的支出减退款计算，并区分原始支出和退款金额。
- **转账与还款**：本人账户间转账、充值及信用卡还款单独标记为资金流动，不计入消费支出；向他人转账可由用户决定是否记为支出。
- **异常输入**：缺少金额、金额冲突或付款状态不明时进入待核对流程，不直接形成正式账单。
- **重复操作**：重复点击通知或保存按钮不得产生第二笔正式记录；已保存记录再次打开时展示详情。
- **删除与修改**：同步更新统计；退款已关联的记录修改或删除时需要处理关联关系。

## 建议技术方案

以下为待验证的技术选型，不代表仓库已经包含对应实现。

| 模块 | 建议方案 | 目的 |
| --- | --- | --- |
| 客户端 | Swift 与 SwiftUI | 构建原生页面和系统交互 |
| 本地存储 | 根据最低系统版本选择 Core Data 或 SwiftData | 保存账单、分类、来源事件与迁移版本 |
| 系统动作 | App Intents 与快捷指令 | 提供接收交易信息、创建候选记录的入口 |
| 提醒与跳转 | UserNotifications 与应用路由 | 在具备权限及运行条件时提醒并定位记录 |
| 截图处理 | Vision OCR 与 Share Extension | 用户分享截图后本地识别金额 |
| 数据交换 | CSV 导出与校验导入 | 支持用户迁移和恢复数据 |

建议将界面、账单业务规则、本地存储和交易接入分别组织。所有接入入口先生成统一的候选交易，再经过校验、去重和用户确认，避免不同入口产生不同统计口径。

原始通知文本和截图默认不长期保存，提取必要字段后尽量丢弃；诊断日志不写入完整支付文本、银行账号或其他敏感信息。第一版不依赖云端 AI 识别付款数据。

| 2 产品与数据设计 | 第 3 周 | 页面原型、账单模型、统计规则、验收用例和首版范围 |
| 3 核心开发 | 第 4 至 6 周 | 接入入口、待记账、通知跳转、分类保存、账单列表及本地存储 |
| 4 完善与测试 | 第 7 至 8 周 | 汇总统计、异常处理、数据导出恢复、权限与兼容测试 |

每个阶段结束后复核工作量，截图识别等 P1 功能可后续增加。云同步与商业化在核心流程通过试用验证后单独规划。

## 兼容性测试与验收

建立覆盖“系统版本 × 设备 × 支付渠道 × 支付场景”的测试矩阵。系统版本至少覆盖拟支持的最低版本和发布时主流版本，设备至少覆盖两代真机；自动化依赖真机测试，不能只使用模拟器。

测试场景包括：锁屏与解锁、App 前台与后台、App 未运行、通知权限拒绝、专注模式、网络断开、重复事件、付款失败、退款、相同金额连续付款及跨日跨月统计。记录自动化配置、触发次数、金额正确次数、延迟和失败原因。

| 验收项 | 建议通过标准 |
| --- | --- |
| 核心链路 | 点击提醒可打开对应候选记录，预填金额并分类保存 |
| 金额正确性 | 对声明支持且字段完整的验证样本，金额与币种匹配率 100%；缺失或歧义输入转待核对 |
| 接入稳定性 | 每个声明支持的配置至少验证 20 笔有效样本；记录成功率和延迟，初步目标为成功率不低于 95% |
| 去重 | 重复事件不重复入账，同金额的独立付款可分别保存 |
| 统计 | 未确认记录不计入支出，退款及资金流动按定义计算，编辑删除后结果一致 |
| 数据恢复 | 重启后记录保留，导出后可校验导入恢复；异常文件不得破坏原有数据 |
| 权限降级 | 拒绝通知权限或自动化不可用时，基础记账和账单查看仍正常 |

上述百分比为内部验证目标，不代表对所有用户的成功率保证。小样本仅用于决定能否进入试用，还需通过更大范围试用评估系统差异与长期稳定性。

## 主要风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 支付事件或金额不可获取 | 无法实现自动提醒预填 | 将真机验证前置，按场景声明支持范围，提供分享及手动入口 |
| 用户配置步骤较多 | 首次使用容易放弃 | 提供配置指引、状态说明和测试流程，减少重复设置 |
| 系统或支付 App 更新 | 原有接入失效或字段变化 | 接入逻辑独立维护，保留回归用例，允许停用失效入口 |
| 通知展示受系统影响 | 提醒延迟或不可见 | 不保证即时弹出，保留已接收的待记账记录，并提供故障排查 |
| 误识别或重复记录 | 用户不信任账单和统计 | 入账前确认，歧义提示，去重与撤销机制 |
| 设备丢失或误删除 | 财务数据丢失 | 提供可验证的导出恢复流程，提醒用户定期备份 |
| 权限与审核要求 | 分发计划受影响 | 使用公开能力，最小化权限，准备真实的配置及审核演示材料 |

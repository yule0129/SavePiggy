# SavePiggy 手机原型

Windows 开发，通过浏览器或 Expo Go 在 iPhone 上预览基础记账，通过 Android 原生构建测试微信付款通知候选。支持手动记账和用户主动提供的 CSV 账单导入，不调用个人微信支付流水接口。

1.0 阶段当前 Android 测试版本为 1.0.2。通知读取、通知提醒和分类悬浮窗分别由用户授权；接入默认停止，手动开启后最多运行 5 分钟，进程重启不自动续期。候选先保存在本机待记账，用户在 App 或悬浮窗中确认分类后计入支出。

已知真机限制：vivo S9 上付款成功页不弹窗，返回微信首页后弹出。桌面及微信首页的后台演示弹窗可显示；付款页通知时机和显示限制尚未确定，不能承诺立即弹出。详见 [1.0 交付记录](../docs/V1_DELIVERY.md) 和 [Android 模块说明](modules/payment-inbox/README.md)。网页、iPhone、Expo Go 不提供该通知监听与悬浮窗功能。

## 电脑浏览器预览

日常调整界面和记账逻辑时可直接在电脑上预览，无需每次扫码，也无需 Expo 登录。

```powershell
cd F:\SavePiggy\mobile
npm run web
```

浏览器通常会自动打开；没有打开时访问终端显示的本地网址。也可以在已经运行 `npm start` 的终端按 `w` 打开网页版。保持终端开启，修改代码后页面会自动更新。

浏览器支持模拟付款、分类保存、账单编辑删除与汇总。确认框使用浏览器的确定和取消按钮。网页账单只保存在当前浏览器，与 iPhone 数据不互通。清除网站数据、使用无痕模式或更换访问地址可能无法保留记录。

浏览器开发者工具的设备模式可用于检查窄屏布局，但不等同于 iPhone 真机。系统通知、快捷指令、锁屏与后台运行等能力后续仍须手机验证。

## iPhone 启动

在 PowerShell 中执行：

```powershell
cd F:\SavePiggy\mobile
npm install
npx expo login
npm start
```

电脑与手机连接同一个 Wi-Fi。手机 Expo Go 登录与电脑相同的 Expo 账号，使用 iPhone 相机扫描终端二维码并在 Expo Go 中打开。服务运行期间请保持终端开启。

若局域网无法连接，先检查 Windows 是否允许 Node.js 通过专用网络防火墙。不要关闭整个防火墙。也可尝试 `npx expo start --tunnel`，按提示安装隧道依赖；此方式需要网络服务可用。

模板使用 Expo SDK 58。请更新 Expo Go；如提示 SDK 不兼容，记录 Expo Go 支持的 SDK 版本，再调整依赖，不要单独修改 React Native 版本。

## 第一次体验

首页固定展示本月累计支出、账单笔数、单笔最高支出及分类分布。点击紫色汇总卡片进入 `/expenses` 支出明细页，在那里切换月度或年度账单；点击年月可打开选择器，按年份选择月份或查看全年。左右箭头切换相邻期间，“回到本月”返回当前月份。金额、笔数和按日期分组的账单同步筛选，仅包含已保存记录。支出日期按当前设备本地日历归属；记账和编辑页面可填写 `YYYY-MM-DD` 补记历史账单。浏览器与手机各自存储数据，不能用两个设备的数据互相验证汇总。

1. 首页点击“模拟付款 ¥28”，选择“去分类”。
2. 确认金额已填入 28.00，选择“餐饮”，点击“保存账单”。
3. 在账单列表查看记录，回首页确认本月汇总为 28.00。
4. 再模拟一笔，选择“稍后处理”：待记账数量增加，总额仍为 28.00。
5. 从待记账中打开记录，分类保存，总额变为 56.00。
6. 编辑一笔金额，再删除一笔，检查总额随之变化。
7. 重新加载项目，确认已保存账单和待记账记录仍然存在。

每笔模拟数据都标注来源。已保存模拟账单会计入汇总，可逐笔删除。手动记账取消后不会创建记录，模拟付款取消分类后仍保留待记账记录。

## 手动记账与半自动导入

手动记账填写金额、商家、支出日期、支付渠道、备注和分类后保存。支付渠道支持微信、支付宝、银行卡、现金、Apple Pay、其他；历史记录没有渠道时按“其他”展示，不会导致已有账单无法读取。

半自动入口位于首页“导入已有账单”和待记账页。先下载模板，再选择填好的 CSV。预览时可逐行勾选并直接修改分类，提供两种处理方式：选择“添加到待记账”，全部记录留待逐笔确认；或核对分类后点击“确认分类并入账”，已分类记录批量计入统计，未分类记录仍进入待记账。取消选择文件不写入数据；CSV 格式错误时不部分导入。

CSV 分类为空时，优先沿用同商家、同渠道的已确认历史分类；历史存在冲突则要求手动选择，不使用模拟账单或待记账作为学习依据。没有历史时，使用本地商家关键词规则建议分类；无匹配或多类别匹配时保留未分类。文件中已有的有效分类不会被建议覆盖，文件中的无效分类仍需手动核对。预览标明“沿用历史”“商家建议”“文件分类”，用户可以逐行调整。所有建议在本地生成，不调用云端模型。

批量入账仍需用户点击确认，疑似重复默认不选；保存前重新核对重复情况，预览后出现新的疑似重复会跳过并提示。此功能减少逐笔操作，不代表付款后自动读取交易。

当前只支持人民币 UTF-8 CSV，单次最大 2 MB、1000 条。**不能直接导入微信、支付宝的原始导出文件、Excel、ZIP 或图片**；先将内容整理为模板格式。文件仅在设备中解析，不上传服务器。

| 列名 | 必填 | 格式及规则 |
| --- | --- | --- |
| 日期 | 是 | YYYY-MM-DD，例如 2026-10-26 |
| 金额 | 是 | 正数，最多两位小数，不含货币符号或千分位 |
| 商家 | 是 | 最多 60 字 |
| 类型 | 是 | 支出可导入；收入、退款、转账、充值、还款跳过 |
| 支付渠道 | 是 | 最多 30 字，例如微信、支付宝、银行卡 |
| 交易号 | 否 | 按文本保留原始值，防止长号码变成科学计数法 |
| 分类 | 否 | 现有分类可预填；其他分类清空并提示，等待手动选择 |
| 状态 | 否 | 若包含此列，须明确填写成功、已完成、支付成功或交易成功；失败、退款等状态跳过 |
| 备注 | 否 | 最多 200 字；含逗号或换行时按 CSV 规范使用双引号 |

表头顺序可调整，必填列不可省略。模板含一笔示例数据，使用前应替换。

同一支付渠道和交易号相同的记录按来源识别为重复，不可再次选择；同一交易号对应不同金额、日期或商家时提示冲突。没有交易号或可能跨渠道重复时无法可靠自动判断：日期、金额、商家和渠道相同的记录标为疑似重复，默认不勾选，用户可核对后主动选择。不同支付渠道的相同消费可能仍是同一交易，必须核对，不能仅依赖自动去重。编辑导入账单后保留原始来源用于再次导入核对；删除或忽略记录后重新导入可再次出现。

浏览器会下载模板文件；iPhone 会打开系统分享菜单以保存模板，选择账单时使用系统文件选择器。浏览器流程已自动验证；iPhone 文件选择、分享与取消操作仍需真机验证。

## 验证命令

```powershell
npm run typecheck
npm test
npm run lint
npx expo export --platform ios
npx expo export --platform web
```

自动检查覆盖金额精度、月度统计和存储数据校验。iOS JavaScript 打包通过不代表真机交互已验证，仍须执行上述手机体验步骤。

## 当前边界

- 演示提醒是应用内模拟弹窗；Android 集成测试包另外提供通知候选提醒，尚待真机验证。
- 仅实现人民币支出，不含退款、转账、导出恢复、加密和云备份。Android 微信通知候选模块已生成测试 APK，尚待集成版真机验收；它不调用个人微信账单接口。
- 数据使用 AsyncStorage 保存在设备中，未加密；请使用测试数据，卸载、清理 Expo Go 数据或更换项目运行环境可能无法保留记录。
- 若读取失败，暂停写入并提示重试，避免损坏的数据被空列表覆盖。
- 当前是开发测试阶段，尚未上架。Android arm64 测试 APK 已完成本地构建与成品权限检查，见 [接入模块说明](modules/payment-inbox/README.md)；签名仅供测试，正式分发仍需配置发布签名并验收。
- 2026 年 10 月 26 日的依赖审计报告包含 5 项 high 告警，涉及 Expo CLI 依赖链中的 node-forge、zod 及上层包。正式发布前需评估兼容的修复版本；不要执行会把 Expo 降级到旧主版本的 `npm audit fix --force`。

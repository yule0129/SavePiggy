# SavePiggy 1.0 阶段交付记录

记录日期：2026-11-04。当前 Android 测试版本 1.0.2 / versionCode 3。本阶段按用户确认冻结现有行为，继续迭代留待后续版本。项目尚未上架，不代表所有支付场景及手机型号已经通过验收。

## 已交付功能

- 首页显示本月已入账支出合计、笔数及分类分布，点击进入明细，按月份或年份筛选。
- 手动录入金额、商家、日期、支付渠道、备注和分类；支持编辑、删除及本地持久化。
- UTF-8 人民币 CSV 模板导入、校验、重复及疑似重复提示、分类建议、预览调整、批量确认。不能直接兼容所有微信/支付宝原始导出文件。
- 待记账与正式支出分开，未确认候选不计入统计；分类建议不擅自覆盖用户的有效分类。
- Android 本地 Expo 模块监听已授权的微信支付标题通知，提取单一无歧义金额，生成待记账及可点击提醒。
- 用户可单独授权悬浮窗并开启分类弹窗：显示金额与 8 个类别，核对后点击类别直接保存到本机；再次打开 App 时同步至账本合计。关闭或超时则保留待记账。
- 8 秒延迟的后台演示弹窗不生成账单；诊断页面显示通知回调、金额提取和弹窗尝试的时间及状态。

## 真机验证与已知限制

测试设备为 vivo S9、Android 13、OriginOS 3、微信 8.0.68。以下为用户操作反馈及工具检查，不是多设备兼容性认证：

| 场景 | 本阶段结果 |
| --- | --- |
| 安装、打开首页 | 用户确认正常 |
| 真实微信付款金额 | 用户确认可提取；独立验证工具曾匹配 0.01 元实际消费 |
| 桌面与微信首页后台演示弹窗 | 用户确认可显示 |
| 真实付款分类弹窗 | 付款成功页不显示，返回微信首页后显示；无需返回 SavePiggy |
| 诊断截图 | 最近一次回调、候选提取和窗口尝试均为 20:19:22，进程状态标为后台；系统接受窗口不证明当时实际可见 |
| 红包 | 未取得有效通知事件，暂不支持 |
| 转账、退款等 | 通知中明确识别时排除，不能当作消费支出 |

不能承诺“付款成功页立即弹出”。现有证据还无法区分源 App 延迟发布通知与特定付款页面隐藏窗口，不继续仅靠要求放宽权限归因。通知不存在或没有金额时，本方案无法提前获得付款数据。当前只有手动开启的 5 分钟测试，不提供全天候接入、跨机兼容性或所有支付方式覆盖承诺。

## 权限与数据

- 系统通知使用权范围较广，代码过滤微信不等于系统只授权微信；必须由用户自行开启或撤销。
- 通知提醒与“显示在其他应用上层”单独申请，分类弹窗默认关闭。不自动操作微信，不使用无障碍服务。
- 原生队列仅保存金额、时间、单向去重标识及用户确认的分类，不保存通知原文、联系人或商家。候选可在停止后保留；原生队列写入 JS 账本后才确认移除。
- 诊断字段保留于进程内存。系统日志只记录固定处理状态及应用进程状态，不记录金额和通知原文。
- 成品未声明联网、录音或广泛存储权限；自动备份关闭。账本和队列未提供应用级加密、云备份或完整导出恢复，卸载或清理数据可能丢失账本。

## 验证与复现

本轮 lint、TypeScript 检查与 23 项 JavaScript 测试通过。Java 金额解析用例通过。Android arm64-v8a release 测试 APK 完整构建和签名验证通过，1.0.0 至 1.0.2 的测试签名证书一致。使用调试签名，不能直接当作商店发布包。

```powershell
cd F:\SavePiggy\mobile
npm ci
npm run lint
npm run typecheck
npm test
.\build-android-local.ps1
```

本地构建脚本默认使用 `F:\Android_SDK` 和项目内的便携 Java 17、Gradle 缓存；其他开发者可传入 `-JavaRoot` 与 `-SdkRoot`。通过 Expo prebuild 生成原生工程，本地模块位于 `mobile/modules/payment-inbox`；Windows CMake 路径调整由 config plugin 维护。

APK、签名文件、依赖目录、SDK 和构建缓存不提交源码仓库。本机交付 APK 位于 `F:\SavePiggy\builds\SavePiggy-android-test-1.0.2.apk`。独立 `notification-probe` 是历史数据源验证工具，不是正式记账入口。
